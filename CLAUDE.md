# FlexEngine

## Goals
A lightweight, flexible 2D engine inspired by Godot, Unity and Unreal:
- A standalone editor (`FlexEditor.exe`) that opens **projects**. Each opened project runs in its own editor process.
- Games are written as a C++ **game module** (a DLL per project) that the editor loads.
- The editor exports a final `game.exe` (built from `FlexRuntime`) as **Development** (with debug tools) or **Shipping** (without).

- There are no tests yet.

## Solution structure
- `Build/FlexConfiguration.props` (imported before `Microsoft.Cpp.props`) and `Build/FlexCommon.props` (imported after) hold all shared settings. Every new `.vcxproj` imports both, so settings aren't repeated per project.
- `Source/Core/` → **FlexCore.dll**. Contains all engine systems. Public classes use `FLEX_API` (`Core/Core.h`). It's a DLL so the editor, the runtime and game modules share one copy of the engine state.
- `Source/Editor/` → **FlexEditorCore.dll** (`FlexEditorCore.vcxproj`: the whole editor UI plus Dear ImGui docking, exported with `IMGUI_API=__declspec(dllexport)` so plugins share one ImGui context) and **FlexEditor.exe** (`FlexEditor.vcxproj`: only `Main.cpp`, which calls `RunEditor(argc, argv)` from `Editor/EditorCore.h`). Classes and functions plugins may use are marked `FLEX_EDITOR_API` (`AssetDatabase`, `ThumbnailCache`, `OutputLog`, `FileDialog`, `InspectorArchive`, `SceneUndo`, `BackgroundJob`, `TextureImporter::*`, `SceneEditing::*`, `BuildTools::*`); header-only types (`EditorWindow`, `AssetEditor`, `EditorContext`, `Selection`) need no export.
- **Editor plugins** are DLLs in `Binaries/<Config>/Plugins/`, see *Editor plugins* below. The engine's own plugins live in `Source/Plugins/<Name>/` (in the solution, not built in Shipping): `Source/Plugins/Paint/` → **FlexPaint.dll**. A plugin project imports `Build/FlexEditorPlugin.props` after `FlexCommon.props` (output folder, `IMGUI_API` as dllimport, links `FlexEditorCore.lib`/`FlexCore.lib`/`SDL3.lib`, debugger starts the editor).
- `Source/Runtime/` → **FlexRuntime.exe**. The game player that will become an exported `game.exe`. Console window in Debug/Development, no console in Shipping. `FlexRuntime.exe --project <file.flexproj> [--scene <file.scene>] [--benchmark SECONDS]` loads the project's game module and runs the scene (the project's Start Scene unless `--scene`), reading assets straight from `Content/` through `Core/Assets/ContentAssetSource` (read-only; exported games will use cooked data). Without `--project` it runs the single `.flexproj` next to the exe (how a built game starts); without any project it only opens a window.
- `Samples/SpriteStorm/` is a **sample project** written the way a user writes one: `SpriteStorm.flexproj`, `Content/` (the Archer sprite sheet with 43 tight sprites, `Main.scene` with a Camera, four static wall colliders and a `SpriteSwarm`), and `Source/SpriteStorm.vcxproj` (in the solution) that builds the game module `SpriteStorm.dll` next to the engine exes. Its components `SpriteSwarm` (spawns N bouncing sprites, each the next sprite of the sheet) and `Spin`, and its systems `SpawnSwarms` (Start) and `SpinSprites` (Update), use only engine APIs. Open it in the editor and press Play, or run `FlexRuntime.exe --project <path>/SpriteStorm.flexproj`. 100,000 sprites run at ~75 fps in Development/Shipping (Debug is far slower). The swarm's colliders use layer 2 with mask 1 (they hit the walls, never each other) and `Friction = 0`; the project sets `RestitutionThreshold = 0` so slow sprites still bounce off the walls.
- `Samples/PhysicsDemo/` is the **rigid-body sample**, its scene built entirely in the editor: a heavy red `Cannonball` (Mass 4) with a `Launcher` (game code: `Delay`, `Velocity`, `AngularVelocity`; the FixedUpdate system `LaunchBodies` sets the body's velocity once) is shot at a 2x6 tower of `Box`es (Mass 1, Friction 0.6, Restitution 0) with a light blue `TopBall` (Mass 0.5, Restitution 0.55) on top, between a `Ground` and two walls. The boxes tumble without bouncing, the ball bounces a few times, and everything falls asleep. `Source/PhysicsDemo.vcxproj` is in the engine solution like SpriteStorm's.
- `Dependencies/` holds vendored libraries: SDL3 3.4.18 (`SDL3/include`, `SDL3/lib/x64`) and Dear ImGui 1.92.9b-docking with its SDL3 + SDL_Renderer3 backends. `SDL3.dll` is copied to `Binaries/` by FlexCore's build.
- **ImGui images use the texture's own filter** (`Texture::SetFilter`), so pixel art stays sharp in thumbnails, the Texture Editor and the Viewport. The vendored SDL_Renderer backend is changed for this (lines marked `FlexEngine:`, re-apply them when updating ImGui): `DrawCallback_SetSamplerNearest`/`Linear` override the filter only for the draws that follow them and restore the texture afterwards; `DrawCallback_ResetRenderState` goes back to each texture's own filter.
- Includes are relative to `Source/`: `#include "Core/Engine.h"`.
- **`Core/Graphics/Renderer`** owns the process's single `SDL_Renderer` (`Renderer::Init(window)`). GPU resources are created through it so the backend can change later. Call `Renderer::EndFrame()` after `SDL_RenderPresent` (editor and runtime do): it frees GPU textures replaced during the frame. **Shutdown order:** release all assets (`AssetManager::Shutdown()` and drop every `shared_ptr`) before `Renderer::Shutdown()`.
- **`Core/Graphics/SpriteBatch`** collects quads (textured or solid, tinted) and draws them with `SDL_RenderGeometry`, one draw call per run of quads with the same texture (max 32,768 quads per call). `Draw` is inline; call `Flush()` before presenting. `SpriteVertex` matches `SDL_Vertex`.
- **Sprites in the world:** `SpriteRenderer` component (`AssetId` = a Sprite or a whole Texture, `Tint`, `Order`; size = the sprite's pixels times the transform's scale; caches the loaded asset in the component). `Core/Graphics/SpriteRenderSystem`: `CollectSprites(world, items)` (sorted by `Order`, skipped when already in order; the last item is on top, also used for picking; the resolved quad is cached in the component), `DrawSprites(items, batch, view)`, `ResetSpriteCaches(world)`. `SpriteBatch::DrawTransformed` draws rotated/scaled quads. `Camera2D` (header-only: `Position` = world point at the centre, `Zoom` = pixels per unit) gives the view matrix.
- **`Core/Physics/Collision2D.h`** is header-only: `BounceCircleInsideRect`, `BounceCircleOffRect` (pushes out and reflects relative to a moving box) and `ClampRectInside` (simple helpers for game code; the physics doesn't use them).
- **Physics** (`Core/Physics/Physics2D`, rigid bodies with mass and rotation):
  - `RigidBody2D`: `Type` (Static/Kinematic/Dynamic, saved as text), `Mass` (only ratios matter; inertia comes from the collider), `Velocity`, `AngularVelocity` (rad/s), `GravityScale`, `LinearDrag`/`AngularDrag` (fraction lost per second), `Friction` (0.5), `Restitution` (0), `bFixedRotation`, `bCanSleep`; runtime `bIsSleeping`/`SleepTimer`. Setting a velocity wakes a sleeping body. Two bodies combine `sqrt(frictionA * frictionB)` and `max(restitution)`; a collider without a body uses `DefaultFriction`/`DefaultRestitution`.
  - `BoxCollider2D` (`Size`/`Offset`, **turns with the transform**, scaled by it) and `CircleCollider2D` (`Radius`/`Offset`), both with `Layer`/`Mask` bits: two colliders touch when `(layerA & maskB) && (layerB & maskA)`. One collider per body (with both, the box is used); the body turns around the collider's centre. Dynamic and kinematic bodies move their **local** Transform (bodies should be roots); static colliders use their WorldTransform and may be children. `ColliderShape2D::FromBox/FromCircle` gives the exact world shape (also used for gizmos).
  - `PhysicsWorld2D` (owned by `GameInstance`, `Reset()` per run) keeps contacts between steps. `Step(world, dt, settings)`: uniform-grid broadphase (moving bodies that can't touch anything are just integrated in place, so 100k swarms stay cheap), manifolds for box-box (SAT + clipping, 2 points), box-circle and circle-circle, kept up to `LinearSlop` apart (contact margin); then `Substeps` sub-steps of gravity/drag, warm-started sequential impulses (friction, then normal impulses; both points of a face contact solved together with Box2D's block solver; highest contacts first) and integration; then position correction (`PositionIterations`), island sleeping and write-back. Run `UpdateWorldTransforms` afterwards. `Core/Physics/Contacts2D` holds the internal solver bodies, manifolds and narrowphase.
  - `PhysicsSettings` (project-wide, `[Physics version=1]` section of the `.flexproj`, edited in the editor's **Project** window, used from the next Play): `Gravity` (980 down), `FixedTimeStep`, `Substeps` (8), `VelocityIterations` (2 per sub-step), `PositionIterations` (3), `RestitutionThreshold` (60 units/s: slower hits don't bounce), `LinearSlop` (0.5), `AllowSleep`, `TimeToSleep` (0.5 s), `SleepLinearSpeed`, `SleepAngularSpeed`. Stacks stay stable mainly through sub-steps; balls have no rolling resistance (use `AngularDrag`).
  - Known limits: no continuous collision (fast small bodies can tunnel), no joints, no polygon colliders, no compound bodies; changing a moving body's layers, or a body to Static, counts for the fast swarm path from the next step.
- **`Camera` component** (`Core/Graphics/Camera`): `ViewSize` world units around the entity, `Background`. `FindMainCamera(world)` (lowest entity index), `GetCameraViewRect`, `FitCamera(worldTransform, camera, viewportSize)` (letterboxed Camera2D). The editor Viewport draws every camera's view rectangle.

## Game code (game modules)
- A project's game code is **`<ProjectName>.dll`**, built with the same configuration as the engine. `GameModule::FindModuleFile` looks in `<Project>/Binaries/<Config>/`, then next to the running exe. Loading it is all it takes: components register with `FLEX_REGISTER_COMPONENT`, systems with **`FLEX_REGISTER_SYSTEM(Phase, Function)`** (`Core/Game/SystemRegistery`; a system is `void Function(World&, float deltaTime)`; phases `Start` (once), `FixedUpdate` (every fixed step, before physics), `Update` (every frame); systems of a phase run sorted by name). One module per process; FlexRuntime never unloads it. **A module must be rebuilt when the engine changes** (struct layouts cross the DLL boundary); the editor warns when the module is older than FlexCore.dll.
- **`Core/Game/GameInstance`** is the frame loop shared by FlexRuntime and the editor's Play mode: `Begin` (Start systems), `Tick` (fixed steps of `PhysicsSettings::FixedTimeStep`, max 5 per tick: FixedUpdate systems then `PhysicsWorld.Step` with the active project's `PhysicsSettings`, read in `Begin`; then Update systems; then `UpdateWorldTransforms`; `world.ApplyCommands()` after every system), `Render` (clears with the main camera's background and draws the sprites fitted to the viewport).
- `AssetManager::GetSubAssets(parentId)` lists a texture's sprites through the current `AssetSource` (game code doesn't see the editor's AssetDatabase).
- **Scripts** (`Editor/ProjectScripts`): a project's C++ lives in `<Project>/Source/`. **Scripts > New Script...** writes `<Name>.h/.cpp` from a template (Component, System, or Component + System; namespace = project name) and, the first time, generates `Source/<Name>.vcxproj` + `<Name>.sln` (marked "Generated by FlexEditor", no absolute paths, safe to commit; compiles every `.h/.cpp` under `Source/` by wildcard; output `<Project>/Binaries/<Config>/`, intermediates `<Project>/Intermediate/`; F5 in Visual Studio starts the editor on the project). The engine's location comes from `Saved/FlexEngine.props`, rewritten by the editor on every start (per machine). A `.vcxproj` without the marker (the SpriteStorm sample, part of the engine solution) is used as it is.
- **Hot reload:** after a successful Recompile the editor saves the scene as text, clears it, `GameModule::Unload` (marks the module's component types **stale** in `ComponentRegistery` — found by checking whether their functions live in the DLL — and removes its systems), loads a fresh copy of the rebuilt DLL (its types re-register, keeping their ids, with possibly new layouts) and loads the scene back: fields that still exist keep their values, components the module no longer has stay as unknown sections. Stale types aren't found by name or listed in Add Component. Play is stopped first.
- **Recompile** (Scripts menu, F7) builds the module with MSBuild (found with `vswhere`, `-p:BuildProjectReferences=false` so the loaded FlexCore is never rebuilt) on a background thread (`Editor/BuildTools`: `RunProcess`, `BackgroundJob`); the log goes to the **Output** window (`Editor/OutputLog` + `OutputWindow`, which also shows every `SDL_Log` line; errors red, warnings yellow). The Content window has a **Source (C++)** folder listing the scripts (double-click opens one).
- **Build Project** (File menu, `Editor/ProjectBuilder`): Development or Shipping, into `<Output>/<Name>/` (default output `<Project>/Builds/`, added to the project's `.gitignore`): builds the module in that configuration, then copies `FlexRuntime.exe` as `<Name>.exe`, `FlexCore.dll`, `SDL3.dll`, `<Name>.dll`, the `.flexproj` and `Content/` as it is (cooked data comes later) except **editor-only assets** and their `.meta` (`AssetDatabase::GetEditorOnlyExtensions()`, e.g. paintings), plus a `.flexbuild` marker — only a folder with that marker is ever replaced. Needs the engine's binaries of that configuration (otherwise it says to build FlexEngine.sln in it). Runs on a background thread; progress in Output.
- The project file stores the **Start Scene** (`StartScene = uid(...)`, `.flexproj` version 2) and the physics settings (`[Physics]` section, defaults while it's missing), both set in the editor's Project window.

## Project system
- A project is a folder holding `<Name>.flexproj` (FlexEngine text format, `[Project version=2]`), `Content/`, `Saved/` (per machine), optionally `Source/` + `<Name>.sln` (game code), and a `.gitignore` (`Saved/`, `Binaries/`, `Intermediate/`, `Builds/`). Project names are letters, digits and `_`, starting with a letter, because they will become game-module names.
- `Flex::Project` (Core) holds **one active project per process**. Opening another project always starts a new `FlexEditor.exe` process (`EditorApp::LaunchEditor`), so nothing ever gets unloaded.
- `FlexEditor.exe` with no arguments shows the `ProjectBrowser`. `FlexEditor.exe --project <file>` (or just `<file>.flexproj`) opens the editor for that project.
- The ImGui layout is saved per project in `Saved/EditorLayout.ini`. Recent projects are kept in `EditorPreferences.ini` next to `FlexEditor.exe`, so nothing is written to AppData.
- Strings are UTF-8 everywhere. Convert with `Utf8ToPath` / `PathToUtf8` (`Core/FileSystem.h`), never by implicit `std::filesystem::path` ↔ `std::string` conversion.
- Native file dialogs (`Editor/FileDialog`) call back on another thread. Results are polled on the main thread.
- Other systems may keep their own sections in the `.flexproj` through `Project::GetDocument()`; `Save()` writes them back unchanged (e.g. `[EditorPlugins]`).

## Editor windows (`Source/Editor/`)
- Every dockable window derives from `EditorWindow` (`Draw()` with `BeginWindow`/`EndWindow`; the tab's close button clears `bIsOpen`). `EditorApp` owns the **panels** (Content, Inspector, Project, ...) and lists them in the **Windows** menu (toggle on/off, Reset Layout). Which panels are open is saved per project in `Saved/EditorLayout.ini` (`[FlexEditorWindows][Open]`). The first start of a project builds a default dock layout: Hierarchy left, Inspector (+ Entities tab) right, Content/Project/Output bottom, Viewport centre; a moment later Inspector and Content are brought to the front.
- Windows share an `EditorContext`: the `AssetDatabase`, `ThumbnailCache`, the current `Selection` (shown by the Inspector), `AssetRevision` (bumps on every refresh) and the `OpenAsset`/`RefreshAssets` callbacks.
- **Hierarchy** (`HierarchyWindow`): tree of the scene's GameObjects. Drag an object onto another to parent it, onto empty space to make it a root; drag an asset from Content onto an object (child) or empty space (root) to create a GameObject. Right-click: create empty (child), rename (F2), move up/down, unparent, duplicate (Ctrl+D: the object and its children with new Uids, placed right after it), delete (Del). Changes are queued while the tree is drawn. Selecting something elsewhere opens its parents.
- **Viewport** (`ViewportWindow`): the scene drawn into its own render target with a grid (red/green axes). Left click selects (sprites, or the cross drawn for GameObjects without a sprite), dragging moves the selection, right/middle drag pans, wheel zooms around the mouse, F frames the selection, Del deletes, Ctrl+D duplicates. Dropping a texture/sprite creates a GameObject at the mouse. The **Colliders** toggle draws every collider's outline in the editor view and the Game View (white static, green dynamic, grey sleeping, blue kinematic, orange selected; circles show their rotation; at most 5,000). While playing, the toolbar shows bodies, sleeping bodies and contact points.
- **Scene files in the editor:** File > New/Open/Save (Ctrl+S)/Save As; double-clicking a `.scene` in Content opens it. A changed scene asks "Save changes?" before New/Open/quitting; the window title shows the scene name and `*` when changed (`EditorContext::SceneRevision` vs `SavedSceneRevision`). The last opened scene is stored in `Saved/EditorLayout.ini` (`[FlexEditorWindows][Scene]`) and reopened on start. The layout is saved explicitly before the windows are destroyed.
- **Entities** (`EntitiesWindow`, tab next to the Inspector): every live entity of the edited world, lightweight ones included (e.g. 100k sprites while playing). One row per archetype (component set + count; filter by component name), open it to list its entities (clipped, fast at 100k), select one to see its components: editable through `InspectorArchive` when they have `Serialize` (one undo step per finished edit), `Parent`/`Children` shown as links, others as "N bytes, no Serialize". "Select in Hierarchy" for GameObjects.
- **Inspector** (`InspectorWindow`): for a GameObject its name, then every component that has a `Serialize` function (`SceneSerializer::GetSavedComponents`: Transform first, then by name) with its fields, drawn by running `Serialize` through `Editor/InspectorArchive` (a Load-mode archive whose `Field()`s are widgets editing in place: bool checkbox, numbers drag fields, string text input, `Uid` asset slot with thumbnail: click opens a picker popup (search box + scrollable list with thumbnails), or drop an asset from Content, `Vector2` one row, `Color` colour picker; float fields named `Rotation` show degrees until `FLEX_PROPERTY` metadata exists). Remove with the header's `x` or right-click (not Transform/GameObjectInfo); **Add Component** lists every registered type with `Serialize` + default constructor. Each finished edit is one undo step. For an asset: info, preview, texture import settings.
- `Archive::Field` for `Vector2`, `Vector2Int` and `Color` is virtual (same default group behaviour) so the Inspector can show them as one widget.
- **Undo/redo** (`Editor/SceneUndo`, Edit menu, Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z): after every finished edit the whole scene is captured in the scene file format (max 100 states); undo/redo load an earlier/later state and restore the selection by Uid, so **Entity handles from before an undo/redo are stale**. Continuous edits record once when they end (viewport drag on mouse release, typed names when the field loses focus) via `SceneEditing::RecordUndo`. New/Open start a fresh history. Undoing back to the saved state makes the scene clean again (`EditorContext::RevisionCounter` keeps revisions unique). Asset edits (Texture Editor) are not part of scene undo.
- **Game module in the editor:** loaded at startup from a copy in `Saved/ModuleCache/` (a new copy per load), so Visual Studio or Recompile can rebuild the DLL while the editor runs; Recompile hot-reloads it. Its components show up in Add Component and load from scene files. Status in the Project window.
- **Play mode** (Viewport toolbar Play/Stop, F5, File menu): saves the scene in memory, runs it with `EditorContext::Game` (a `GameInstance`), and Stop loads it back, so changes made while playing are discarded. Saving and undo are off while playing. **Game View** (on while playing) shows what the main Camera sees; editing input works in the editor view only. **File > Run Standalone** starts FlexRuntime on the saved scene file.
- All scene changes from editor windows go through `Editor/SceneEditing` (create from asset / empty, delete, reparent, move sibling, rename, set world position), so every window behaves the same. The edited scene is `EditorContext::EditorScene`; while editing, the editor calls `UpdateWorldTransforms` every frame but runs no game systems.
- **Asset editors** derive from `AssetEditor` (one window per opened asset, id `Prefix_<uid>`). `EditorApp::AssetOpeners` maps an asset type to what double-click does; opening an asset that already has a window focuses it (`OnReopen(subAssetId)`). A sprite opens its texture's editor with the sprite selected. Closed asset editors are destroyed (their asset is released).

## Editor plugins (`Editor/EditorPlugin.h`, `Editor/EditorPlugins`)
- A plugin is a DLL with one `EditorPlugin` (`GetName()`, `OnLoad(EditorPluginHost&)`, `OnUnload()`) exported by `FLEX_EDITOR_PLUGIN(Type)` in one `.cpp` (exports `FlexEditorPluginApiVersion` + `FlexCreateEditorPlugin`). Bump `EditorPluginApiVersion` when the API or a struct plugins use changes; plugins built for another version are skipped, and the Plugins window warns when a plugin is older than `FlexEditorCore.dll`.
- `EditorPluginManager::LoadAll` runs once a project is open, after the editor's own asset types and windows and **before the first asset scan**; nothing is loaded in the Project Browser. Plugins are **never unloaded** while the editor runs (their windows and callbacks live in the DLL); `UnloadAll` calls `OnUnload` at shutdown after every window is destroyed and before assets are released.
- `EditorPluginHost` (implemented by `EditorApp`): `GetContext()`, `GetMainWindow()` (file dialogs), `RegisterAssetType(type, extensions, metaInit, AssetTypeFlags)` (`EditorOnly` = never copied into builds), `RegisterAssetOpener`, `OpenAssetEditor`, `AddPanel` (Windows menu), `AddMenuItem(menu, label, shortcut, action, isEnabled)` (`File`/`Edit`/`Scripts`/`Windows` get the items after a separator; another name makes a new menu before Windows; the shortcut is only shown), `AddContentCreateItem` (Content right-click > Create, gets the shown folder), `RegisterThumbnail(type, fn)` (`ThumbnailCache::SetProvider`; `ThumbnailCache::Invalidate(uid)` drops one preview), `AddDrawCallback(fn)` (every frame after the windows, for a plugin's own popups). `EditorPluginApiVersion` is 2.
- Per project in the `.flexproj`: `[EditorPlugins version=1]` with `Name = false` to disable one (missing = enabled). The **Plugins** window (bottom dock) lists every DLL with its status and an enable checkbox; changes apply after restarting the editor.
- Windows are drawn by index, so a window may open another (e.g. an asset editor) while it draws.

## Paint plugin (`Source/Plugins/Paint/`, FlexPaint.dll)
- **Painting** asset (`.flexpaint`, `AssetTypeFlags::EditorOnly`, so never in builds): a layered image in the FlexEngine text format, `[Painting version=1]` (`Width`, `Height`, `ExportPath` relative to Content/, `ExportTexture` uid, `ExportOnSave`, `Palette` as RGBA hex) then one `[Layer version=1]` per layer, bottom to top (`Name`, `Visible`, `Locked`, `Opacity`, `Blend` = Normal/Multiply/Add/Screen, `Pixels` = the layer as a PNG in base64). Max 4096 x 4096. A layer that can't be decoded loads empty. `Painting.h`: `Layer` (pixels in a `shared_ptr<Image>`, copied on write by `Painting::EditPixels` so undo states share unchanged layers), `Composite`/`Flatten`/`MergeDown` (straight-alpha RGBA8, W3C separable blending). `PaintImage.h`: `Pixel`, `PixelRect`, `Image` (crop/paste/flip/rotate/resize), `BlendOver`, PNG in memory and files through SDL 3.4 (`SDL_SavePNG_IO`/`SDL_LoadPNG_IO`), base64.
- Created with Content right-click > Create > **Painting...** or **Assets > New Painting...** (size presets, background, or *start from a texture*: the texture becomes the first layer and exporting overwrites it with the same Uid). Double-click opens the **Paint window** (`PaintEditor`, one per painting).
- **Paint window:** tools Pencil (N), Brush (B: size, hardness, opacity, spacing; a stroke never builds up over itself), Eraser (E), Fill (G: tolerance, contiguous, sample all layers), Picker (I; Alt+click with any tool), Line (L, Shift = 45°), Rectangle (U), Ellipse (O; outline width or filled, Shift = square/circle), Select (M; drag inside to move the pixels; painting stays inside the selection), Move (V). Right mouse paints the secondary colour, X swaps, `[`/`]` size. Mirror X/Y, pixel grid from 8x, wheel zoom around the mouse, middle or Space+drag pans, F fits. Edit: cut/copy (shared clipboard between paintings), paste as a new layer, clear (Del), select all / deselect (Ctrl+A / Ctrl+D, Esc). Layers: new, duplicate, delete, drag or arrows to reorder, visibility, lock, opacity, blend, merge down, flatten, flip, import an image file or a project texture as a layer. Canvas: canvas size (crop/extend, optionally centred), image size (nearest neighbour), flip, rotate 90°. Palette per painting (DawnBringer 32 by default; click = primary, right-click = secondary, Shift+click removes).
- **Undo** (Ctrl+Z / Ctrl+Y while the window is focused, separate from scene undo): whole-document snapshots that share unchanged layers, max 100 steps and 512 MB. Ctrl+S saves (focused route wins over the scene's Ctrl+S); closing with unsaved changes asks.
- **Export** (Ctrl+E, and on save when `ExportOnSave`): the visible layers flattened into `ExportPath` (`.png`), assets refreshed (the first export creates the `.meta`; later ones keep the Uid, so sprites and references survive), the Uid stored in the painting (it wins over the path when the png was moved), and an already-loaded texture updated in place with `Texture::UpdatePixels`, so the scene shows it at once. Overwriting a png the painting didn't export asks first.

## Serialization
- **Files in a project** (`.flexproj`, `.meta`, `.scene`, and later prefabs) use the FlexEngine **text format** (`Core/Serialization/TextDocument`): `[Type attr=value]` sections, then `Key = Value` lines, with `;` comments. Load + save keeps unknown keys, sections and comments. Values are `true`, `-12`, `0.1` (shortest round-trip), `"escaped string"` and `uid(16 hex)`.
- **Exported games** will read **cooked binary** files (`BinaryWriter`/`BinaryReader`). These are order-based with no field names, and rebuilt on every export. Never use binary for files inside a project.
- **Typed asset references:** `archive.Field("Asset", AssetId, { Sprite::TypeName, Texture::TypeName })` limits a Uid field to those asset types (any type name the asset database knows: `Texture::TypeName`, `Sprite::TypeName`, `SceneSerializer::AssetTypeName`, ...). Saved exactly like a plain Uid; the Inspector only lists and accepts those types. A plain `Field(name, Uid&)` allows any asset.
- Classes save and load through **one** `Serialize(Archive&)` function. Call `SerializeVersion(CurrentVersion)` first and branch on the returned version for upgrades. Missing or unreadable fields keep their defaults and add a warning, so loading never hard-fails.
- Paths written into files use `/` separators (`PathToGenericUtf8`).
- **Scene files** (`Core/Scene/SceneSerializer`, `.scene`, asset type `Scene`): `[Scene version=1]`, then per GameObject (depth-first in Hierarchy order) a `[GameObject version=1]` section (`Name`, `Id`, `Parent` for children) followed by one section per component that has a `Serialize` function (Transform first, then by name). Loading rebuilds the same order; unknown component sections are kept in a hidden `PreservedComponents` component and written back unchanged. `SaveGameObjects`/`LoadGameObjects` do the same for a subtree (undo, later prefabs), `SaveComponent`/`LoadComponent` for one component.
- **Component registration:** `ComponentTypeInfo` also has `DefaultConstruct` and `Serialize` (nullptr when the type has none; types without `Serialize` aren't saved). `FLEX_REGISTER_COMPONENT(Type)` in one `.cpp` registers a type at load time so it can be found by name before first use (all Core components do this; game modules must too). `World::AddComponentById`/`GetComponentById`/`RemoveComponentById` work with a `ComponentId`.
- Planned: reflection (`FLEX_PROPERTY`) on top of `Archive`, so one declaration gives saving, the inspector and undo.

## Assets
- `Flex::Uid` is a random 64-bit id written as 16 hex characters, and 0 means none. **Assets reference each other by Uid, never by path.**
- `Editor/AssetDatabase` scans `Content/`. Types registered with `AssetTypeFlags::EditorOnly` (`IsEditorOnly`, `GetEditorOnlyExtensions`) are source files only the editor uses. Every file of a registered type gets a sidecar `<file>.meta` (`[Meta version=1]`, `Id`, `Type`, plus later import settings) that must be committed and moved together with the file.
- On refresh it creates missing `.meta` files and gives copies (duplicate ids, including sub-asset ids) new ids. The file that owned the id at the previous refresh keeps it: that's remembered in memory and in `Saved/AssetOwners.cache` (per machine). Only without any history does the first path alphabetically win. It **never deletes**: an orphaned `.meta` is only reported, and a `.meta` it can't parse is left untouched and the asset skipped.
- **Sub-assets:** `RegisterSubAssetType(parent, section, type)` turns every `[section]` in a parent's `.meta` into its own asset (`AssetInfo::ParentId`, `Name`). They're listed right after their parent. `FindByPath` only returns file assets.
- **`AssetManager`** (Core) loads assets **by Uid** through a pluggable `AssetSource`, and shares them: the same Uid always gives the same `std::shared_ptr`. It only keeps weak references, so an asset is freed when its last user lets go. The editor plugs in `EditorAssetSource` (source files + `.meta`); exported games will plug in a cooked-data source. Failed loads aren't retried until `AssetManager::ClearFailures()`.
- **Textures:** `.png` and `.bmp`, loaded by SDL 3.4 itself (no SDL_image). Generated images use `Texture::CreateFromPixels` (RGBA8); `Texture::UpdatePixels(w, h, rgba)` replaces a loaded texture's image in place (every user sees it at once; a new size gets a new GPU texture, the old one is freed by `Renderer::EndFrame`). Import settings live in the `.meta` `[Import]` section; for now that's `Filter` = `"PixelArt"` (default), `"Nearest"` or `"Linear"`. Editor-side code is in `Editor/TextureImporter`. Changing the filter applies at once to every user of the texture.
- **Sprites** (`Core/Assets/Sprite`) are sub-assets stored as `[Sprite version=1]` sections in their texture's `.meta`: `Id`, `Name`, `Rect.X/Y/Width/Height` (pixels, top-left origin) and `Pivot.X/Y` (0-1 inside the rect, y down). A `Sprite` holds a `shared_ptr` to its `Texture`, so any number of sprites use **one** GPU texture, and the texture is freed when the last sprite and every other user let go. `Sprite::ApplyDefinition` updates an already-loaded sprite after an edit.
- **Texture Editor:** one window per texture. The filter is saved immediately (also editable in the Inspector). Sprite edits (drag to cut, select, name/rect/pivot, grid slicing with `Editor/SpriteSlicer`) stay a working copy until **Apply** writes them to the `.meta` and refreshes the database; closing the window with unapplied edits asks first. Re-slicing with "Replace" **keeps the Id of every sprite whose name stays the same**, so references survive. Sprite names should be unique per texture.
- The **Content** window (`Editor/ContentBrowser`) shows the folders of `Content/` and the assets of the chosen folder as thumbnail tiles (textures can be expanded to show their sprites). Click selects (Inspector), double-click opens the asset's editor, right-click on empty space opens Create (plugin items, `EditorContext::ContentCreateItems`) and Show in Explorer, and tiles are drag sources (`AssetPayloadType`, payload `Uid`). Thumbnails (`Editor/ThumbnailCache`) keep their textures loaded while the editor runs.

## Math (`Core/Math/`, include `Core/Math/Math.h`)
- **Header-only and mostly `constexpr`**, so it inlines into hot loops in game code (no DLL calls). Don't move math into `.cpp` files.
- **Conventions:** x right, **y down** (like SDL/Godot/image files). Angles are **radians** in code; a positive angle is **clockwise on screen**. 1 world unit = 1 pixel at zoom 1 (the camera can change that later).
- `Vector2` (float `x, y`), `Vector2Int` (grid/pixel coordinates, hashable), `Matrix2x3` (affine: `dirX`, `dirY`, `orig`; `A * B` applies B first, so world = parent * local; `FromTRS` builds scale-rotate-translate directly), `Rect` (top-left + size, half-open), `Color` (float RGBA, `ToRGBA8` for SDL), `Random` (PCG32, seedable/deterministic, one per system or thread), `MathUtils` (`Pi`, degree/radian conversion, `Lerp`, `WrapAngle`, `DeltaAngle`, ...).
- Equality operators are **exact**; use `NearlyEqual` for tolerance.
- `Archive::Field` supports `Vector2`, `Vector2Int` and `Color` (stored as groups like `Position.X`; virtual so the Inspector can override them). Derived archives need `using Archive::Field;` so these overloads aren't hidden.

## World / ECS (`Core/World/`, include `Core/World/World.h`)
- **One ECS world, our own archetype storage.** Every GameObject **is** an entity: an entity plus a `GameObjectInfo` component (`Core/World/GameObject.h`: `Name`, `Id` = Uid that stays the same in scene files). The hierarchy belongs to transforms, not to `GameObjectInfo`, so lightweight entities can be parented too. **Lightweight entities** (bullets, RTS units) have only data components and are spawned in bulk. The same systems process both. *(GameObjects, behaviours with `Start`/`Update`/`OnDestroy`, systems, reflection and rendering are later patches.)*
- Particles are arrays inside an emitter component, not entities.
- **`Entity`** = `Index` + `Generation` (8 bytes). `Entity{}` is invalid (generation 0). Destroying bumps the slot's generation, so stale handles stop being alive. Freed slots are reused LIFO.
- **Components** are structs marked with `FLEX_COMPONENT(Name)`. Types are identified **by that name** through `ComponentRegistery` in FlexCore (lazy registration on first use, dense `ComponentId`), so game-module DLLs get the same ids. Ids depend on registration order: never save them, save names. A second type with the same name but another size/alignment asserts. Components must be movable; non-trivial types (`std::string`) are fine.
- **`Archetype`** = one table per exact component set: one contiguous 64-byte-aligned column per component plus an `Entity` column. Rows are packed with **swap-and-pop**, so row order isn't stable. Add/remove moves the row to another archetype; moves are cached as edges.
- **`World`** is an instance (not a singleton): `Spawn(components...)`, `SpawnBatch<Ts...>(count, init)` (default-constructs, reuses freed slots, no vector returned), `Destroy`, `IsAlive`, `AddComponent<T>(e, value)` (replaces if present, `nullptr` if dead), `RemoveComponent<T>`, `GetComponent<T>` (`nullptr` if missing; pointer valid until the next structural change), `HasComponent<T>`.
- **Queries:** `world.Each<Position, const Velocity>([](Position&, const Velocity&) {...})`, optionally with `Entity` as the first parameter. Header templates: FlexCore is called once per matching archetype, never per entity.
- **No structural changes inside `Each`** (asserts with `FLEX_DEBUG_TOOLS`): record them in `world.GetCommands()` (`Spawn` returns a usable reserved handle, `Destroy`, `AddComponent`, `RemoveComponent`) and call `world.ApplyCommands()` at the end of the frame. Commands are applied in order; commands on dead entities are ignored. `Defer(std::function<void(World&)>)` runs any multi-step change (e.g. `Hierarchy::SetParent`) in that same order. Not thread-safe yet.
- **Transforms** (`Core/World/Transform.h`): `Transform` = **local** `Position`, `Rotation` (radians), `Scale`, with `Serialize`. `WorldTransform` = `Matrix2x3` (world = parent * local), written by `UpdateWorldTransforms(world)` and read by rendering/physics/editor. Spawn both together. No Z: draw order belongs to the renderer. `UpdateWorldTransforms` always recomputes (no dirty flags): roots in flat loops, then children depth-first. `ComputeWorldMatrix(world, e)` walks up the parents without relying on `WorldTransform`.
- **Hierarchy** (`Core/World/Hierarchy.h`): `Parent { Entity }` and `Children { vector<Entity> }` components, kept in sync **only** through `Hierarchy::SetParent(world, child, parent, bKeepWorldTransform = true)` (refuses cycles; `Entity{}` detaches; `Children` is removed when empty). Also `GetParent`, `GetChildren`, `GetRoot`, `DestroyWithChildren`. `World::Destroy` stays raw: it leaves children orphaned, and an orphan is treated as a root (warning once with `FLEX_DEBUG_TOOLS`). Setting a parent is a structural change, so inside `Each` use `GetCommands().Defer(...)`.
- **`Core/Scene/Scene`** = a World of GameObjects plus the order of the root objects and a Uid -> Entity lookup. `CreateGameObject(name, parent, localTransform, id)` spawns Transform + WorldTransform + GameObjectInfo; `DestroyGameObject` (with children), `SetParent(child, parent, siblingIndex)` (keeps the world position), `GetSiblingIndex`/`SetSiblingIndex`, `GetRoots()` (also picks up changes made directly through Hierarchy), `FindByUid`, `Clear`. `Hierarchy::SetSiblingIndex` orders children; `World::GetComponentIds(entity)` lists an entity's component types.
- `FLEX_ASSERT(condition, message)` (`Core/Core.h`): logs, breaks into the debugger and aborts with `FLEX_DEBUG_TOOLS`; in Shipping the condition isn't evaluated.
- **Benchmark target:** 50,000 moving bullets updated and drawn at 60 fps in a Development build. Patch 09 measured the update only (no drawing yet): ~0.04 ms per frame for 50k `Position += Velocity * dt`, plus ~0.05 ms to apply 1,000 destroys + 1,000 spawns.

## Code conventions
- Everything in `namespace Flex`.
- Classes, methods and members in PascalCase; booleans with a `b` prefix (`bIsRunning`).
- Tabs for indentation, `#pragma once`. Function braces go on a new line; control-flow braces go on the same line.
- New `.cpp`/`.h` files must be added to the matching `.vcxproj`.
- Every module must use the same CRT (`/MDd` Debug, `/MD` otherwise), because STL types cross the DLL boundary. The props files already handle this.

# SpaceAdventure (reference only)
A personal SDL2 + ImGui 2D engine/editor in one VS project (`SpaceAdventure/SpaceAdventure.sln`, Debug|x64 = editor, Release = game). It has a GameObject/Component model with macro-based self-registering registries (`DECLARE_COMPONENT`, `ASSET_LOOKUP`, `DECLARE_SYSTEM`), lazily computed `Transform`s, `.asset` binary files under `Content/` loaded by `AssetManager`, and `SceneManager`/`Renderer` singletons. Known weak spots that FlexEngine should avoid:
- Unversioned binary serialization.
- Scene assets being moved out of the asset manager when a scene is opened.
- Renderer/camera registrations that are never removed.
- Build output committed to git.
